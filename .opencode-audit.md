### Langkah 3 — Pipeline optimasi upload (server) ✅
`server-update.cjs` (live: md5 022bb78b):
- Ganti `multer.diskStorage` → **`sharpStorage`** custom yang, setelah upload:
  - auto-rotate (perbaiki orientasi EXIF),
  - resize max sisi **1600px** tanpa perbesar (`withoutEnlargement`),
  - re-encode kualitas **80** (mozjpeg untuk JPG; untuk PNG pakai compressionLevel 9/palette),
  - **hanya jika lebih kecil** — kalau lebih besar, file asli dipertahankan apa adanya,
  - buat **thumbnail ±400px** (`-thumb` di samping file),
  - nama file tetap `Date.now()+ext` → `req.file.filename`, path DB, format respons **tidak berubah**.
- File non-gambar (PDF dll) disimpan apa adanya (tidak diproses).
- Migrasi `paket_galleries`, `log_foto_sementara`, dst tetap berfungsi (mulai server test terbukti OK).

### Langkah 4 — Rekompresi uploads lama → SUKSES ✅
- 51 file: 9.667 KB → **2.771 KB** (hemat ~71%). Terverifikasi via test server & `du`.
- Terbesar: `1788330415674.JPG` 6000×4000 6.773 KB → **168 KB** (kecepatan halaman terjawab).

### Langkah 5 — Atribut loading/lazy ✅
- Semua **371 tag `<img>`** di `src/` kini punya `loading="lazy"` (31 yang belum ditambahkan) + **`decoding="async"`** (340 ditambahkan).
- Hero asli adalah CSS `background-image` (`IMG_0615.JPG`) → langsung dimuat oleh browser tanpa perlu lazy; tidak ada fetchpriority yang perlu ditambah (bukan `<img>`).

### Langkah 6 — Caching gambar ✅
- `app.use('/uploads', express.static('uploads', { maxAge: '30d', setHeaders, ... }))` → `Cache-Control: public, max-age=2592000, immutable` untuk jpg/png/webp/avif/gif/svg.
